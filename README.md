KafkaGo
Библиотека для работы с Kafka на Go с готовыми заготовками producer и consumer.

# 📋 Описание

Проект предоставляет переиспользуемую логику для создания producer и consumer с использованием двух популярных библиотек:

В apps/ находятся примеры интеграции этих заготовок в простые приложения для демонстрации использования.
💡 Идея проекта: если понадобится написать consumer или producer — уже есть готовые заготовки и примеры.
🚀 Быстрый старт

📋 Требования

- Go 1.21+
- Docker & Docker Compose
- Make

Work with Kafka using [kafka-go](https://github.com/segmentio/kafka-go) library (producer).
Work with Kafka using [franz-go](https://github.com/twmb/franz-go/pkg/kgo) library (consumer).

- Поднять зависимости:

```
# Поднять Kafka + KafkaUI
  make kafka_up
# Поднять Redis (для идемпотентности)
  make consumer_redis_up
```

- Запустить consumer:

```
cd apps/kafka-consumer
go run cmd/main.go
```

- Запустить producer:

```
cd apps/kafka-producer
go run cmd/main.go
```

# 🔧 Основные возможности

- Consumer (franz-go)
  ✅ Graceful shutdown — корректное завершение с ожиданием обработки текущих сообщений
  ✅ Обработка паник — перехват паник в обработчике, отправка в DLQ
  ✅ DLQ (Dead Letter Queue) — асинхронная отправка ошибочных сообщений
  ✅ Идемпотентность через Redis — предотвращение дублирующей обработки
  ✅ Синхронная загрузка конфигов — все конфиги загружаются при старте
  ✅ Ручной коммит оффсетов — контроль над подтверждением сообщений
  ✅ Статистика — счетчики обработанных сообщений и DLQ
  ✅ Логирование — структурированное логирование через slog

- Producer (kafka-go)
  ✅ Асинхронная/синхронная отправка — настраивается через конфиг
  ✅ Сжатие — поддержка snappy, gzip, lz4, zstd
  ✅ Retry стратегии — настраиваемое количество попыток
  ✅ JSON сериализация — автоматическая сериализация доменных событий
  ✅ Партиционирование по ключу — гарантия порядка для одного ключа

- Идемпотентность через Redis
  ✅ Проверка EventID — автоматическая проверка в Redis перед обработкой
  ✅ TTL 24 часа — автоматическое удаление старых записей
  ✅ Fail-open стратегия — при ошибке Redis сообщение обрабатывается (без блокировки)
  ✅ Логирование дубликатов — пропуск и логирование повторных сообщений

# 📊 Логирование

Логирование реализовано через встроенный пакет slog.
Уровни логирования: DEBUG, INFO, WARN, ERROR
Форматы:
text — человекочитаемый формат (по умолчанию)
json — структурированный формат для интеграции с системами мониторинга

# Graceful Shutdown

Consumer поддерживает graceful shutdown:
Перехватывает сигналы: SIGINT (Ctrl+C), SIGTERM, SIGQUIT, SIGHUP
Ожидает завершения обработки текущего батча
Таймаут ожидания: 30 секунд
При таймауте — принудительное завершение

# ❓ FAQ

Q: Как добавить кастомный обработчик сообщений?
A: Реализуйте интерфейс kafka.MessageHandler:

```
type MyHandler struct {}

func (h *MyHandler) HandleMessage(ctx context.Context, msg *kafka.Message) error {
    // ваша бизнес-логика
    return nil
}

func (h *MyHandler) OnBatchProcessed(batchSize int) {
    // хук после обработки батча
}
```

Q: Как настроить идемпотентность?
A: Идемпотентность настраивается через Redis. В сообщении должен быть event_id. Подробнее в разделе Идемпотентность.

Q: Как отправить сообщение в DLQ?
A: При ошибке в HandleMessage сообщение автоматически отправляется в DLQ. Настройки DLQ в dlq_manager.yml.

Q: Как изменить TTL для идемпотентности?
A: В store_handler.go измените h.cacheTTL = 24 \* time.Hour.

Q: Можно ли использовать producer на franz-go?
A: Да, в pkg/kafka/franz-go-producer/ есть заготовка для producer на franz-go.

Q: Как запустить consumer без Redis?
A: Можно отключить идемпотентность или использовать fail-open режим.
